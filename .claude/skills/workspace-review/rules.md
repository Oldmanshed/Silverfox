# workspace-review — standing rules

These are the user's preferences for the Friday review. They override the
defaults in `SKILL.md`. The skill proposes edits here (RULES lane) when it
notices a pattern; the user approves them like any other change.

- Propose at most 5 upgrades per run. Rank by time saved.
- Every proposal needs concrete evidence: file names, counts, dates or quoted prompts.
- Never delete; archive to `_archive/` instead.
- Keep the final summary short: list only what changed, plus the undo command.
- Don't propose anything rejected in the last 4 weeks unless the evidence has clearly grown.
